# Delivery closure

Match the terminal action to the request: a ready candidate, PR, integration and deployment are different outcomes. An explicit analysis, review, candidate-only or PR-only request defines a bounded endpoint. For “finish autonomously” or equivalent end-to-end work, preserve the overall outcome through implementation, validation and delivery. Resolve the concrete delivery target using prior instructions and the project workflow; readiness is an intermediate milestone.

Continue actions already authorized in the conversation, including integration when covered. Where a remaining merge, release or deployment needs user authority or an unresolved target, first finish the authorized work needed to make that decision concrete and reviewable. Then state the exact remaining action and needed decision. Report the task as partial at that boundary. General autonomy alone establishes neither a merge target nor public-release authority.

Inspect provider/Git evidence and current requirements rather than treating an attempt status as proof of every action. After confirmed integration, complete applicable combined checks, specification publication and change closure, retain evidence and useful lessons, and reconcile owned resources. A PR-only handoff retains its pending integration work and resources with their current state.

Before cleanup, retain useful verification outputs, prototype findings and lessons in durable locations or canonical records. Confirm the retained paths are readable outside the worktree/process being removed. Summarize unresolved issues so another agent can resume.

Inspect the owned worker/process handles, worktree, branch and dirty files. Stop only resources established as belonging to this task, using the host or project procedure. Preserve unrelated or unintegrated work. The CLI records delivery and retains the worktree; actual cleanup uses explicit Git/host operations. Read `aep --skill implement --ref git` for shared-store transport, record conflicts or uncertain integration identity. Confirm the integration branch retains the shared ledger, applicable published specifications and useful evidence before completing closure.

Remove a disposable worktree only after its useful work and evidence are retained and its intended integration is confirmed. Verify resources actually stopped/removed, or report them as retained with the reason. “Done” in the ledger describes work status, not cleanup evidence.

Refresh affected Feature Map operations using the real product behavior. Capture lessons that change future action through `aep --skill reflect`; avoid filling a lessons log merely to complete a ritual. Release/deployment checks remain environment-specific and separate from a local merge.
