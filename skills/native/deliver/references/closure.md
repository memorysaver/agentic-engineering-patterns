# Delivery closure

Match the terminal action to the request: a ready candidate, PR, integration and deployment are different outcomes. Inspect provider/Git evidence and current requirements rather than treating an attempt status as proof of every action.

Before cleanup, retain useful verification outputs, prototype findings and lessons in durable locations or canonical records. Confirm the retained paths are readable outside the worktree/process being removed. Summarize unresolved issues so another agent can resume.

Inspect the owned worker/process handles, worktree, branch and dirty files. Stop only resources established as belonging to this task, using the host or project procedure. Preserve unrelated or unintegrated work. The CLI records delivery and retains the worktree; actual cleanup uses explicit Git/host operations. Read `aep --skill implement --ref git` when recovery or integration identity is uncertain.

Remove a disposable worktree only after its useful work and evidence are retained and its intended integration is confirmed. Verify resources actually stopped/removed, or report them as retained with the reason. “Done” in the ledger describes work status, not cleanup evidence.

Refresh affected Feature Map operations using the real product behavior. Capture lessons that change future action through `aep --skill reflect`; avoid filling a lessons log merely to complete a ritual. Release/deployment checks remain environment-specific and separate from a local merge.
