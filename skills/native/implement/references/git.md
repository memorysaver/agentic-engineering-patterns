# Git and worktree operations

Resolve the integration target from the request and project policy, then inspect the actual ref and commit. Use an explicit reproducible base containing the accepted contract and completed dependencies. Branch names alone establish neither freshness nor authority.

Before changing history, inspect `git status`, the diff and recent commits in the correct worktree. Keep scope and resource ownership clear. Resolve conflicts against accepted intent, then rerun affected verification at the resulting head. Rebase/cherry-pick creates a new candidate whose old evidence may be stale.

Use `aep worktree inspect --attempt <id>` and Git's worktree inventory to reconcile paths and branch ownership. Reflog and retained commits can recover lost local work; inspect recovery candidates before replacing current files. Provider integration evidence is checked through delivery commands.

For cleanup, read `aep --skill deliver --ref closure`. The CLI retains worktrees after recording delivery; removal is an explicit Git/host operation after useful work and evidence are preserved. A clean worktree alone does not establish that its branch was integrated.

Keep the implementation candidate in its assigned worktree and record attempts, checks, reviews and delivery through `aep --root <shared-store>`. Commit accepted context needed by dispatch into the chosen base. Later execution receipts belong in the shared store; copying them into the candidate can introduce paths outside the story's scope and change the verified head.

Retain shared-store changes on the appropriate context/integration branch. After confirmed product integration, reconcile those records and published specifications into the intended integration branch using the project's Git procedure. Compare conflicting story snapshots with actual attempt, provider and delivery evidence; preserve the established state and useful history. Check the combined result and synchronize its retained records before removing owned resources. Scope checks still apply to every candidate path; an unexpected ledger diff calls for restoring the intended branch arrangement with all useful work preserved.

Before integration, inspect remote movement and the pending shared-store diff. Keep execution receipts in the shared checkout; retain probe outputs in the configured lessons/evidence location when they are observations rather than accepted contract inputs. Files under a linked change directory participate in verification freshness, including files added there during integration.

Reconcile product integration into the shared checkout before publishing and committing closure records. When a story snapshot conflicts, inspect both parents and the referenced delivery/attempt records, retain each historical receipt, and select the confirmed current integration pointer. Preserve unrelated fields and ownership edits; a whole-file ours/theirs choice is not a record-aware merge. Check the resulting native records and Git diff before synchronization. Context-only movement on an already integrated candidate can be reverified and published without another product PR.
